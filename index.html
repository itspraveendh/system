DATA INTEGRITY & WORKFLOWS

Build Every Management Module with Complete Record Operations

Every entity follows a strict operational pipeline: Create, Read, Update, and Delete/Archive with foreign-key constraints, server-side data validation, CSRF checks, and atomic MySQL transactions.

Core Record Management & Security Rules

Server-Side Validation: Never trust JavaScript validation alone; sanitize input strings, enforce date ranges, and validate phone/email types in PHP.
Archival Over Hard Deletion: Financial ledgers, payroll records, invoices, and attendance logs use soft deletes or status cancellation to preserve audit trails.
Bulk Import Previews: Map CSV headers to database columns and present an error summary table before committing records to MySQL.
CSV Injection Defense: Prefix spreadsheet formula operators (=, +, -, @) with a single quote during exports.

DEVELOPER METHODOLOGY

How CRUD Works in the FCS Management System

Using Employee Management as the primary example to teach the client's developer the unified record management pattern.

Create

Add an employee via a POST form. Verify required fields, ensure email is unique, hash temporary password, and commit with a PDO prepared statement.

Read

Display active staff in a paginated table. Sanitize all output with htmlspecialchars to prevent cross-site scripting (XSS).

Update

Load the record into an edit form with CSRF validation. Verify the updater has permission, validate modifications, and record changes in the audit log.

Delete / Archive

Set status = 'archived' rather than hard-deleting the row, protecting connected attendance and payroll history from foreign-key failures.

Universal FCS Data Execution Pipeline:

User Form Submit ➔ CSRF Token Check ➔ Server Validation (PHP) ➔ Role Permission Verify ➔ PDO Prepared Statement Bind ➔ Atomic MySQL Execution ➔ Flash Success/Error Message ➔ Append-Only Audit Log
SECURITY BLUEPRINT

Database & Application Security Principles

Core engineering practices that the developer must implement to ensure system security and data reliability.

PDO Prepared Statements

Bind all user inputs via PDO parameters. Never concatenate strings into SQL queries. This provides robust protection against SQL injection attacks.

Password Hashing

Hash credentials using PHP's native password_hash() with bcrypt or Argon2id. Never store plain text passwords or employ legacy algorithms like MD5 or SHA1.

Cryptographic CSRF Tokens

Generate unpredictable CSRF tokens per session and validate them on every state-changing form submission to prevent cross-site request forgery.

Output Escaping (XSS Mitigation)

Escape all dynamic content rendered in HTML contexts using htmlspecialchars($var, ENT_QUOTES, 'UTF-8') to prevent malicious script injection.

Secure Session Config

Configure sessions with HttpOnly, Secure, and SameSite=Strict cookie attributes, and regenerate session IDs on successful login.

Environment-Based Secrets

Store database passwords, SMTP credentials, and encryption keys in environment variables or an isolated configuration file located outside the public web root.
